# 业务总开关

后台入口：**系统设置 → 业务字典 → 业务总开关**。

这是所有分店共用的单一开关，字典键为 `business_enabled`，`1` 表示开启，`0` 表示关闭。仅持有总部管理权限 `store:all` 的员工可以查看和修改；选择不同分店不会改变开关的作用范围。

首次安装默认关闭。升级重启保留已有值，不会自动打开。配置缺失、被归档或值无效时，业务保持关闭。

| 操作 | 关闭时 |
| --- | --- |
| 顾客及员工新建预约 | 禁止 |
| 确认预约、预约改期 | 禁止 |
| 充值及附带赠送 | 禁止 |
| 手动扣减、扫码扣款、明细扣款 | 禁止 |
| 顾客注册、首次微信登录自动建档 | 禁止 |
| 员工微信绑定后的自动建档、启动时自动补建会员 | 禁止 |
| 会员／员工微信绑定、生成绑定码、绑定短信验证码 | 禁止 |
| 预约／交易通知订阅登记 | 禁止，客户端配置返回关闭并隐藏入口 |
| 已有账号密码登录、已绑定且满足原认证条件的微信登录 | 保留，不追加微信关联，不自动补全微信会员资料 |
| 后台新增会员、员工、分店、包间、商品、Banner、临时关闭时段 | 禁止，由服务端统一拦截 |
| 后台编辑已有资料、密码／通知设置、启停／上下架、删除 | 禁止 |
| 管理业务总开关 | 保留，仍按原有总部权限校验 |
| 浏览门店、包间、时段，查询会员余额和历史记录 | 保留 |
| 取消、拒绝预约，既有预约到店核销和完成 | 禁止 |

开关在服务端事务内校验，不依赖前端按钮或请求参数。关闭操作会等待已获准的事务完成；关闭成功后，后续预约、充值、扣减请求均被拒绝。历史余额与记录不修改。修改开关与操作日志在同一事务中保存。

关闭后不再接受新的注册、自动建档、绑定和订阅写入。已有账号登录仍更新最近登录时间；网站微信登录的临时认证状态、登录认证状态和操作日志继续写入。已排队的历史通知及预约超时处理仍按原配置执行。因此这是限制用户业务的展示模式，不是数据库全面只读。

后台接口为 `GET /api/business-dictionary` 与 `PUT /api/business-dictionary`，更新请求示例：`{"enabled":false}`。

持久化表 `t_business_dictionary` 由启动升级组件幂等创建，包含公共创建时间、更新时间及删除标识。部署此功能后，请由总部管理员在确认开放业务时主动打开开关。此功能不需要修改微信小程序即可拦截旧版本请求。
