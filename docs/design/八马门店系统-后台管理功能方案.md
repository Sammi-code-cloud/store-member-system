# 八马门店系统 · 后台管理功能方案

本方案用于确定后台页面内容和开发范围。下文“建议”与验收要求均为目标功能，不代表已经实现。

## 1. 后台菜单

| 菜单 | 页面主要内容 | 优先级 |
| --- | --- | --- |
| 工作台 | 今日经营指标、今日预约、待处理事项、快捷入口 | 首期 |
| 预约管理 | 预约列表、房间日历、订单详情、到店核销、取消与改期 | 首期 |
| 房间管理 | 房间资料、价格、营业时段、开放预订、临时停用 | 首期 |
| 顾客管理 | 全部已注册顾客、顾客档案、余额、消费与预约记录 | 首期 |
| 员工管理 | 添加员工、编辑资料、分配角色、在职与停用、重置密码 | 首期 |
| 经营统计 | 消费、充值、新增顾客、预约和房间使用情况 | 首期 |
| 资金流水 | 消费订单、充值记录、余额变动、退款处理记录 | 首期，退款执行另行接入 |
| 商品管理 | 茶叶与茶点、价格、库存、上下架 | 复用已有模块 |
| 门店设置 | 门店资料、营业时间、预约规则、联系方式 | 首期 |
| 操作记录 | 员工修改、价格变更、核销、充值、取消等操作追踪 | 首期 |
| 会员营销 | 会员等级、积分、优惠券、储值赠送、生日关怀 | 后续 |

已扩展为多分店：总部管理员新增及切换分店，包间、预约、员工和经营记录按授权门店隔离；顾客账号和会员余额跨店共享。顾客先选分店再预订包间。多店汇总报表与跨店结算后续再做。

## 2. 工作台

- 统计卡片：今日实收消费、今日充值、今日预约、待到店预约、今日新增顾客、当前可用房间。
- 今日预约：时间、房间、顾客、联系电话、人数、状态，支持进入详情和核销。
- 待处理：即将到店、超时未到、待处理取消申请、低库存商品。
- 快捷操作：添加员工、新增房间、代客预约、查找顾客、代客充值。
- 页面展示统计日期、最近刷新时间；加载失败需提示重试，不能将失败显示为零。

## 3. 员工管理

列表字段：工号、姓名、手机号、角色、所属门店、账号状态、创建时间。

添加员工：姓名、手机号、初始密码、角色、所属门店；工号由系统生成。手机号需校验格式与重复，密码输入默认隐藏。

操作：编辑资料、调整角色、重置密码、启用或停用。离职员工保留历史操作和业务关联，停用后禁止继续使用旧登录态操作。

建议角色：管理员负责账号和设置；店长负责门店经营；店员负责接待、预约和核销。充值、退款、报表导出等权限单独分配；后端同步校验，不能只隐藏按钮。

## 4. 可预订房间管理

列表字段：房间名称、封面、类型、容纳人数、每小时价格、是否开放预订、排序。

详情与编辑：图片、介绍、设施、人数范围、计价单位、起订时长、营业时段、可提前预约天数、临时关闭日期或时段。

将“是否开放预订”与“某时段是否空闲”分开：开放中的房间仍可能已被预约；维护中的房间不可新订，已有预约继续保留并提示处理。

房间日历：按日期显示各房间的预约区间、可用时段及临时关闭时段，点击预约查看订单。

关键规则：

- 预约按完整起止区间判断冲突。例如 14:00–16:00 已有预约，15:00–17:00 不允许再次预订；16:00 起订在无需清洁间隔时允许。
- 同一时段的并发请求只能有一个成功；后台代客预约与顾客端使用同一套校验。
- 停用房间、过去时间、超出营业时间、非正时长均不可预订。
- 调整房价只影响新订单，历史订单保留成交价格。
- 有历史订单的房间优先停用或归档，保留订单里的房间名称和价格快照。

## 5. 预约管理

筛选：预约日期、房间、订单状态、顾客姓名或手机号、订单号。

列表字段：订单号、房间、顾客、联系电话、日期、开始与结束时间、人数、应付金额、预约状态、付款状态、来源。

建议预约状态：待到店 → 使用中 → 已完成；待到店可取消或标记未到店。预约状态和付款状态分别保存，核销不能默认等于已付款。

操作：代客预约、详情、到店核销、完成、改期、取消。改期重新检查冲突；取消填写原因并释放时段，退款结果独立记录。重复核销不能重复产生业务影响。

## 6. 顾客管理：所有成功注册或首次登录的顾客自动进入

无需充值、消费或升级会员，成功建立顾客身份即进入顾客列表；没有登录身份的匿名访问者不自动建档。

自动建档流程：顾客注册或首次授权登录成功 → 按可信身份查找 → 不存在则创建顾客和初始账户 → 后台列表可查询；再次登录更新最近登录时间，不重复新增。

微信身份应使用平台返回且经服务端验证的标识；手机号绑定应经过验证。手机号与既有档案冲突时进入明确的账号绑定流程，不能按昵称或客户端传来的手机号直接合并余额。

列表字段：顾客编号、头像或昵称、姓名、手机号（未绑定显示未绑定）、会员等级、余额、累计消费、注册时间、最近登录时间、状态。

筛选：姓名或昵称、手机号、顾客编号、注册日期、会员等级、是否消费、状态。

顾客详情：基本资料、账户余额、充值记录、消费记录、预约记录、标签和门店备注。首次登录且无业务记录时展示清晰空状态。

所有注册用户是“顾客”；普通、金卡、黑金等属于顾客的会员等级。后台名称建议由“会员管理”改为“顾客管理”，避免误以为只有充值用户才可见。

员工端登录与顾客身份分开；同一人可同时是员工和顾客。限制顾客账号时保留历史记录和余额，注明原因，不提供直接随意修改余额的入口。

## 7. 经营统计

支持今日、昨日、近 7 天、近 30 天和自定义日期，并统一按门店时区统计。

| 指标 | 建议口径 |
| --- | --- |
| 消费金额 | 统计区间内成功支付的消费金额；退款单列，同时提供净消费额 |
| 充值金额 | 成功入账的实际充值本金，赠送金额单列 |
| 顾客余额 | 当前账户余额合计，展示为时点数据 |
| 新增顾客 | 区间内首次建档的去重顾客数 |
| 消费顾客 | 区间内成功消费的去重顾客数 |
| 预约数量 | 明确区分“区间内下单”与“预约到店日期在区间内” |
| 房间使用率 | 实际使用时长 ÷ 开放营业时长；临时关闭时段从分母剔除 |
| 房间预订率 | 有效预约占用时长 ÷ 可预订时长，与实际使用率分开展示 |

图表内容：每日消费与充值趋势、新增顾客趋势、预约状态分布、各房间预订排行、员工收款与核销统计。

充值和储值余额消费不能相加作为营业收入，避免重复统计。尚未采集实际到店和结束时间时，不展示虚构的实际使用率，可先展示预订率。

## 8. 建议补充的配套模块

资金流水：关联订单号、顾客、金额、变动前后余额、支付方式、操作员工、时间；支持筛选和明细查看。退款需关联原交易并控制可退金额，真实支付退款能力另行接入。

门店设置：门店名称、Logo、地址、电话、营业时间、预约须知、取消截止时间、清洁间隔。规则修改记录生效时间，历史订单保留当时约定。

操作记录：记录操作者、时间、对象、动作、变更前后摘要和结果，支持按员工或业务单号追踪；不记录密码和登录令牌。

后续再做：优惠券、积分兑换、生日权益、储值赠送、员工排班与提成、多门店汇总。先让预约、顾客、员工和资金记录形成可用流程。

## 9. 现有项目情况与建议实施顺序

代码检查发现：

- `bama-store-web` 已有员工新增、角色选择、停用、重置密码、茶室增删改、会员列表与账户详情、基础概览、预定核销、代客储值、商品和门店设置。
- 顾客接口明确为免登录演示用途，小程序预约页使用固定会员 ID；真实顾客登录注册与自动建档尚未接通。
- 房间目前以基础资料和启停为主；预约创建依赖唯一索引处理重复，尚未形成完整时间区间冲突校验。
- 当前统计以总量和当日消费为主，尚未覆盖本方案中的日期筛选、趋势和使用率。

建议按以下顺序推进：

1. 接通真实顾客身份、自动建档和后台顾客查询；完成数据访问权限校验。
2. 完善员工资料与角色调整、房间开放规则和预约区间校验。
3. 完善预约详情、状态流转、取消改期和日历。
4. 接入资金流水和统一口径的统计工作台。
5. 补齐操作记录与门店规则设置，再按经营需求增加营销。

## 10. 首期验收场景

- 新顾客成功注册后，无需充值即可在后台查到；再次登录仍只有一条档案。
- 未绑定手机号的授权顾客正常入库；账号冲突不会自动合并资金。
- 新增员工可用分配的权限登录；停用后新旧登录态均无法继续操作。
- 新增并开放房间后顾客端可见；停用后不能通过直接请求新建预约。
- 重叠时间预约被拒绝，边界相接的合法预约可成功，并发不会重复占用。
- 取消释放时段，改期校验新时段；重复核销不重复生效。
- 顾客详情能关联本人预约、充值和消费；空记录不显示演示数据。
- 统计能与指定时间范围的交易明细核对，充值与消费不重复计入。
- 已有关联订单的员工、顾客或房间停用后，历史单据仍可追溯。
