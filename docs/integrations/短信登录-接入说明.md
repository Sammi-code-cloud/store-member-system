# 小程序首次短信绑定

实现版本：小程序 1.0.4。此功能需要配套新后端和已开通的阿里云短信服务；仅更新小程序无法启用短信绑定。

## 登录流程

1. 小程序通过微信登录凭证识别微信身份。未验证绑定的顾客只收到短期绑定凭证，不创建会员、不发放登录令牌。
2. 用户输入本人中国大陆手机号，主动获取验证码。后端调用阿里云短信，验证码有效期 5 分钟，微信绑定凭证也为 5 分钟；过期后重新验证微信。
3. 验证通过后：已有手机号会员关联原账户；新手机号创建账户；同一微信以后直接登录，不重复发短信。
4. 已绑定其他微信、冻结会员、旧微信档案与手机号会员档案冲突时，拒绝自动绑定，交由门店核实处理。此版本不提供自助换绑或自动合并余额。
5. 旧版自动创建的微信顾客需补做验证；若手机号未占用则保留原会员编号、订单及余额。已有账号密码登录仍然可用。

## 阿里云开通与配置

在阿里云短信服务控制台完成服务开通、所需实名资质、短信签名和验证码模板审核，并准备可用短信额度。审核条件以阿里云控制台为准；个人小程序与短信账户的资质审核是不同环节。

模板变量必须包含 `code`，例如“您的验证码为 ${code}，5分钟内有效，请勿泄露给他人”。最终使用已审核通过的模板。参考：[阿里云短信 SDK 接入](https://help.aliyun.com/zh/sms/developer-reference/how-to-use-api-quickly)。

服务器进程环境变量（不要填写在 Git 源码或小程序中）：

| 变量 | 用途 |
| --- | --- |
| `SMS_ENABLED` | 配置完成后设为 `true`，默认 `false` |
| `SMS_ACCESS_KEY_ID` | 专用 RAM 用户的 AccessKey ID |
| `SMS_ACCESS_KEY_SECRET` | 专用 RAM 用户的 AccessKey Secret |
| `SMS_SIGN_NAME` | 审核通过的短信签名 |
| `SMS_TEMPLATE_CODE` | 审核通过的验证码模板编号 |
| `SMS_DAILY_LIMIT` | 全站滚动 24 小时发送尝试上限，默认 100 |
| `SMS_IP_DAILY_LIMIT` | 每个来源地址滚动 24 小时上限，默认 100 |

RAM 权限仅授予发送短信所需能力。可使用服务器受限权限的外部配置 `bama.sms.*` 注入同名配置，禁止提交密钥。运行时通过 HTTPS 调用 `dysmsapi.aliyuncs.com`，不需要将这个域名加入小程序 request 合法域名。小程序只访问本项目后端。

## 校验与限流

- 每个手机号、每个微信身份：60 秒内最多 1 次，滚动 24 小时最多 5 次。另有来源地址和全站额度限制，失败发送也计入限流，避免重试造成费用失控。
- IP 取服务端连接地址，不信任客户端自行传入的转发头；反向代理部署时可能共享同一地址，应根据可信代理配置和业务量调整限制。
- 数据库只保存验证码的 bcrypt 散列，验证码不返回客户端、不写日志。手机号在验证码表中为散列；成功绑定后正常保存到会员档案。
- 验证码绑定手机号及本次微信凭证，最多尝试 5 次。并发校验也只能成功消费一次。绑定冲突后已验证的验证码不会恢复使用。
- 发送成功表示服务商接受请求，不代表运营商已送达；发送失败和服务未开通都不会返回成功。
- 新增表为附加建表，不删除旧业务数据。上线前备份数据库；绑定表和验证码表也应遵守备份访问权限。

## 上线验证

完成真实短信配置后，先在测试环境验证一次真实送达，再同步部署新后端与 1.0.4 小程序体验构建。验证首次绑定、退出后同微信登录不发短信、已有会员余额保持不变，随后再提审发布。

当前本地自动化测试通过模拟短信服务进行验证，不会发送真实短信，也不含生产可用的固定验证码或跳过校验开关。短信未开通前，不将此版本替换线上现有登录流程。
