# 充值与扣款订阅通知

每笔成功充值（含赠送余额）产生一条通知，每笔成功扣款产生一条通知。通知写入与资金变动相同事务的发件表，提交后后台发送；资金事务回滚时不发通知，重复扣款请求不重复入队。

新小程序账号需要先在微信公众平台「订阅消息」添加充值和消费通知模板。将实际模板 ID、字段映射放在服务器外部配置中。以下字段名仅为格式示例，必须按平台实际模板填写，不能直接启用：

```yaml
bama:
  wechat:
    wallet-notice:
      enabled: false
      state: formal
      recharge:
        id: "实际充值模板ID"
        fields:
          amount: amount1
          balance: amount2
          time: time3
      charge:
        id: "实际消费模板ID"
        fields:
          amount: amount1
          balance: amount2
          time: time3
```

可映射值：`amount` 实际余额变动（充值含赠送，扣款为负数）、`gift` 赠送额、`balance` 交易后的余额、`time` 交易时间、`store` 门店名、`order` 交易号、`type` 交易类型、`reason` 变动原因。模板与字段核对后才能将 enabled 改为 true；小程序版本也必须包含订阅入口。

顾客在「我的」或付款码页面主动点击订阅。一次性订阅受微信授权次数限制，不能承诺每次交易必达。服务器用新的微信登录 code 验证顾客微信与已登录会员一致后保存通知接收者；不接受客户端直接提交 OpenID。现有身份表只存身份哈希，无法反推 OpenID，老用户需要重新点击订阅。拒绝订阅不影响记账。

`t_wx_wallet_receiver` 保存当前小程序接收者，`t_wx_wallet_notice` 保存通知任务：PENDING 待发送、SENDING 发送中、SENT 微信已受理、REJECTED 微信明确拒绝（例如 43101 无可用授权）、SKIPPED 无接收者或绑定变化、UNKNOWN 网络或响应结果不确定。SENT 不代表用户已阅读。微信接口不提供业务幂等键，UNKNOWN 不自动重发，避免同一交易重复通知；需要运维核查。发送失败不会回滚已完成的资金交易。

启用前需在体验环境用已授权测试会员核验真实送达，再配置正式模板与版本。不要向真实顾客发送测试通知。发送内容不包含员工密码、令牌或密钥。

当前账户余额变动模板共用于充值和扣款，字段映射为 type→thing8、amount→amount1、balance→amount2、time→date4、reason→thing6。同一模板在订阅弹窗中只请求一次。

## 当前启用方式

生产环境 enabled=true、recharge-enabled=true，充值和扣款均入队。顾客点击首页「付款凭证」时，在用户点击事件中申请余额变动订阅；同意后先登记接收者，再打开付款码。付款码页面另外显示「订阅充值 / 扣减提醒」按钮，支持直接进入页面或重新授权。拒绝或接口失败仍可正常付款；自动刷新付款码不申请订阅。微信授权次数、关注或系统设置等限制仍适用，不保证每笔送达。
