# 会员充值与消费短信

> 2026-09-16：按业务要求停用充值、扣费短信。资金服务已移除短信入队调用，生产配置 `bama.sms.wallet-notice.enabled=false`，交易短信凭据和模板已从活动配置移除。登录验证码、微信通知独立保留。下文仅供历史实现参考，不应据此重新启用。

充值、消费扣减成功后，将短信任务和资金流水在同一个事务中提交，定时任务在提交后发送。无需微信订阅授权，收件人为交易会员的手机号。原微信交易通知保持独立运行。

## 配置

通过外部私有配置或环境变量配置 `bama.sms.wallet-notice`：

```yaml
bama:
  sms:
    wallet-notice:
      enabled: true
      access-key-id: ${WALLET_SMS_ACCESS_KEY_ID}
      access-key-secret: ${WALLET_SMS_ACCESS_KEY_SECRET}
      sign-name: ${WALLET_SMS_SIGN_NAME}
      charge-template: ${WALLET_SMS_CHARGE_TEMPLATE}
      recharge-template: ${WALLET_SMS_RECHARGE_TEMPLATE}
```

这组配置不启用短信验证码登录，也不复用验证码模板。密钥不进入源码、JAR、前端或小程序。

两种模板均使用 `name`、`amount`、`balance` 三个参数。充值金额为实充本金，余额包含本次赠送；消费金额为实际扣减额，使用正数。金额固定两位小数，姓名为空时使用“会员”。

## 状态与防重复

`t_sms_wallet_notice` 使用交易类型和业务单号组成的唯一事件键。重复扣款请求复用原单，不会再次入队；事务回滚不会留下待发送任务。发送前检查会员状态和手机号，手机号变化或无效时跳过，避免误发资金信息。

状态：`PENDING` 待发送、`SENDING` 发送中、`ACCEPTED` 阿里云已受理、`REJECTED` 阿里云明确拒绝、`UNKNOWN` 结果不确定、`SKIPPED` 无效或已变化的收件人。受理不等于运营商最终送达，可用 `provider_id` 在阿里云核查。

阿里云 [SendSms 文档](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms) 说明该接口不支持幂等。SDK 关闭自动重试；超时或进程中断的任务标记 UNKNOWN，不自动重发。明确拒绝同样保留错误码，不盲目重试。发送失败不会撤销已提交的资金交易；修正配置后应先核对供应商发送记录，再决定是否补发。

只发送启用后的新交易通知，不扫描或补发历史流水。暂未提供后台短信状态管理页面，运维可查询通知表和阿里云发送记录。
