# 会员预约成功微信通知

使用当前小程序的「预约提醒」订阅消息模板，独立于 WxPusher 员工通知和会员余额通知。

会员点击「确认信息并提交」时，小程序直接唤起微信订阅授权（不先等待网络请求）。同意后通过微信登录 code 登记接收身份，再提交预约；拒绝、接口不可用或登记失败仍正常提交预约。成功页按登记结果提示是否开通通知。

「预订茶室」页面的门店信息下方也提供「订阅预约成功提醒」按钮，样式与充值/扣减订阅入口一致。登录会员可主动点击授权，不需要提交预约；只在后端已配置模板且微信支持订阅接口时显示。授权返回期间保留当前预约选择，拒绝不影响预约。订阅配额用完后可再次点击，在店员确认预约前完成授权。

店员将 PENDING 预约确认成 WAITING 时，在同一数据库事务生成通知。只有事务成功提交才会发送，重复确认不会重复生成；创建、拒绝、取消不触发预约成功通知。通知包含房间、预约日期时间、预约地址、预约成功状态、联系电话，点击进入「我的」查看预约。

## 后端私有配置

```yaml
bama:
  wechat:
    booking-notice:
      enabled: true
      template-id: <当前小程序预约提醒模板ID>
      state: formal
```

模板字段必须为 `thing1`（预约项目）、`time3`（预约时间）、`thing4`（预约地址）、`phrase7`（预约状态）、`phone_number5`（联系电话）。地址或项目超过 20 字时截断；地址为空用门店名，门店电话不可用时使用预约联系电话。

`GET /api/customer/booking-notices` 返回启用状态和模板 ID；`POST` 提交 `{code}`，仅允许当前登录会员登记。OpenID 由服务端换取，并校验其属于当前小程序及已绑定会员，不接受客户端指定 OpenID。微信账号改变或会员停用后不发送。

## 发布与验证

后端部署后还需上传更新的小程序版本，旧小程序没有预约通知授权入口。开发版本上传、设为体验版、提交审核和正式发布是不同步骤，手机应进入包含本次修改的版本。

测试使用模拟微信和 H2；正式收件需会员在手机允许本次订阅，然后店员确认一条真实预约。微信授权配额由平台管理，登记成功不保证每次送达；没有授权时仍可在「我的预约」查看。

通知保存在 `t_wx_booking_notice`，接收身份保存在 `t_wx_booking_receiver`。PENDING 等待发送，SENT 为微信接口接受，REJECTED 为微信明确拒绝（如 43101），UNKNOWN 为请求结果不明，SKIPPED 为无接收者或身份已改变。后台每 5 秒处理一次，原子领取避免并发重复发送；请求超时和进程中断不自动重发，以免消耗下一次订阅配额。

```sql
SELECT event_key,status,error_code,create_time,update_time
FROM t_wx_booking_notice ORDER BY create_time DESC;
```
