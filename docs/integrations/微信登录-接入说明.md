# 微信登录接入状态

## 扫码登录小程序本身

后台「分店管理」和「门店设置」新增「小程序码」入口，可查看、下载营业分店的微信小程序码。顾客扫码打开 `pages/customer/entry`，确认分店后点击「微信一键登录 / 注册」，进入对应分店的小程序首页；已有顾客会话验证通过后直接进入。这里不会登录电脑后台，也不会授予员工身份。

小程序码只包含 `scene=s=<分店编号>`。入口校验营业分店，暂停营业、无效或不存在的分店不会被自动替换为另一家店。1.0.4 起首次微信登录先短信验证手机号，既有会员档案冲突不自动合并，参见《短信登录-接入说明.md》。

上线准备：

1. 后端配置已有的 `WECHAT_MINI_APP_ID` 和 `WECHAT_MINI_SECRET`，密钥只存后端。按微信平台要求配置服务器 IP 白名单。
2. 将小程序 `.env.example` 复制为被 Git 忽略的 `.env.local`，填写 `VITE_API_BASE_URL=https://你的后端域名`（不带 `/api`）。在微信公众平台配置同一 request 合法域名，重新编译小程序。不要填写 AppSecret；真机不能使用电脑的 localhost。
3. 上传并发布包含 `pages/customer/entry` 的小程序版本，再生成正式码。后端 `WECHAT_MINI_CODE_ENV` 默认 `release`；开发联调可配置为 `trial` 或 `develop`，扫码人员需具备对应体验或开发权限。入口路径校验始终开启。
4. 更新后端及后台页面，在营业分店点击「小程序码」生成并下载，使用真机微信扫一扫完成登录验证。

当前已完成本地逻辑测试和页面构建。真实小程序码生成、微信真机授权、合法域名和发布版本仍需在实际微信环境验证；浏览器预览不能模拟真实微信扫码。

已接入顾客小程序、员工小程序、Web 管理后台和两个浏览器演示端。当前没有微信应用，因此默认关闭真实微信授权，点击入口会提示未配置；账号密码登录继续可用。尚未完成微信开发者工具、真实扫码、线上回调及 MySQL 实库联调。

## 开通后配置

只在后端环境变量配置，禁止写入前端或提交真实密钥：

| 环境变量 | 用途 |
| --- | --- |
| `WECHAT_MINI_APP_ID` | 微信小程序 AppID |
| `WECHAT_MINI_SECRET` | 小程序 AppSecret |
| `WECHAT_WEB_APP_ID` | 开放平台网站应用 AppID |
| `WECHAT_WEB_SECRET` | 网站应用 AppSecret |
| `WECHAT_WEB_REDIRECT_URI` | `https://正式域名/wechat-login.html` |

小程序还需将 `manifest.json` 中的微信 AppID 设置为已开通的 AppID，将 `common/request.js` 后端地址改为 HTTPS 地址，并在微信后台配置请求合法域名。网站应用需开通微信登录并设置对应回调域名。

浏览器微信登录使用同源弹窗：`wechat-login.html`、`wechat-login.js`、`wechat-callback.js` 均在 `bama-store-web/public`。Web 构建自动带入；独立部署 uni-app H5 时也需将这三个文件复制到站点根目录，同时反向代理 `/api` 到后端。`docs/demo-h5/server.js` 已提供这三个资源。

本版一个后端配置对应一个正式网站回调地址，浏览器前端应部署在同一 HTTPS 源下；不同端口或不同域名需要分别配置对应部署，不能直接把任意 localhost 端口作为已开通的微信登录站点。普通浏览器使用网站应用扫码流程；尚未接入公众号内网页 OAuth、原生移动 App 微信 SDK 或企业微信。

## 身份与绑定

- 1.0.4 起，顾客第一次通过微信登录只取得短期绑定凭证，短信验证手机号通过后才关联已有会员或建立新档案。之后同微信直接登录。支持微信返回的 UnionID 关联已配置应用；未返回 UnionID 时按 AppID + OpenID 区分。
- 只有经过本次短信验证的手机号才可用于关联会员，客户端填写手机号或 OpenID 不能直接领取账户。旧微信档案与手机号会员不一致、会员已绑定其他微信等情况必须由门店核实，不自动合并钱包。开通配置及测试见《短信登录-接入说明.md》。
- 员工首次微信登录需验证已有员工手机号和密码，之后沿用原角色、分店与停用状态。不自动新增员工、不自动授予总部权限。同一微信的顾客和员工身份独立。
- 绑定请求和网站 OAuth state 使用服务端五分钟一次性凭证，数据库保存令牌哈希；网站 state 还绑定 HttpOnly、Secure、SameSite=Lax Cookie。绑定失败需重新发起微信授权。
- 小程序只向后端发送临时 code，服务端与微信交换身份；AppSecret、session_key、微信 access_token 不返回客户端。身份索引使用哈希，避免数据库大小写排序规则误合并不同微信身份。

## 验证与启动

执行后端 `mvn -q test`，微信测试模拟微信服务，覆盖顾客去重、跨应用标识、员工绑定、身份隔离、绑定重放、失效 state 和停用账号。模拟只存在于测试类，运行环境没有伪微信登录入口。

执行 Web `npm run build`，再从仓库根目录执行 `node bama-store-miniapp/scripts/build-preview.cjs`，恢复小程序浏览器样式预览。生产上线前仍需真实微信应用和 HTTPS 环境完成端到端联调。

参考入口：[小程序登录凭证校验](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)、[网站应用微信登录](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)。

## 当前本地联调：使用已有 MySQL

后端使用 `local` 配置连接已有 MySQL，端口为 `8092`。数据库密钥在被 Git 忽略的 `src/main/resources/application-local.yml`，微信密钥在 `.local/application-local.yml`。

从项目根目录启动：`powershell -File bama-store-admin/scripts/start-local.ps1`。
网页预览：`node bama-store-web/preview-local.cjs`，默认代理至 `8092`；如设置过 `BAMA_API_TARGET`，请同步修改。
小程序 `common/request.js` 已使用 `localhost:8092`，修改后需在 HBuilderX 重新编译。真机需改成可访问的后端地址。

已核对 MySQL 原有门店、员工、会员、预约数量保持不变。先前 H2 的临时测试账号及预约没有自动合并到 MySQL。微信配置已启用，真实微信登录仍需在微信环境取得 code 后联调。
